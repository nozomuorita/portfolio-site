# ポートフォリオサイト要件定義書

最終更新日: 2026-09-27
対象: NOZOMU ORITA Portfolio

## 1. 文書の目的

本書は、ポートフォリオサイトで実現する価値と対象範囲を定義し、デザイン、実装、テスト、公開方式に共通の判断基準を与えるものです。サイト所有者と開発者は同一ですが、将来の自分や協力者との認識合わせに利用します。

## 2. サイトの目的

### 2.1 主目的

- 氏名、人物像、経歴、研究実績、制作物、資格、技術経験を一つのWebサイトで伝える。
- 採用担当者、技術者、研究関係者などが、短時間で活動の全体像を把握できるようにする。
- GitHub、AtCoder、Codeforces、論文など、詳細情報を持つ外部サイトへの入口を提供する。

### 2.2 副目的

- React、Vite、GitHub Actions、AWS CDK、S3、CloudFront、IAM/OIDCを用いた開発・運用を学ぶ。
- 改修の意図やインフラ構成を文書として残し、再現可能な開発経験にする。

### 2.3 想定閲覧者

| 閲覧者 | 主に知りたい内容 |
| --- | --- |
| 採用担当者 | 人物像、経歴、資格、制作実績 |
| エンジニア | 使用技術、実装経験、GitHub上の成果物 |
| 研究関係者 | 学会発表、受賞、学術論文 |
| 友人・一般閲覧者 | 自己紹介、趣味、活動内容 |
| サイト所有者 | 学習成果、AWS構成、運用履歴 |

## 3. 成功条件

1. 初見の閲覧者が、トップ画面で所有者の氏名とポートフォリオサイトであることを認識できる。
2. 主要情報へ固定ヘッダーまたはスクロールで到達できる。
3. PCとスマートフォンの双方で、情報が欠落せず閲覧できる。
4. `main`ブランチへの反映から、手作業で成果物をコピーせず公開できる。
5. AWS版ではS3を直接公開せず、HTTPSのCloudFront経由で配信できる。
6. 公開後に障害が発生した場合、Gitの正常なコミットを再デプロイして復旧できる。

## 4. 対象範囲

### 4.1 対象に含めるもの

- 1ページ構成の公開ポートフォリオサイト
- Header、Hero、About、Portfolio、Qualifications、Skill、Contact、Footer
- 制作物詳細を表示するモーダル
- BGMの手動再生・停止
- 外部プロフィールおよび論文へのリンク
- PC・タブレット・スマートフォン向けレスポンシブ表示
- GitHub Actionsによる品質確認と自動デプロイ
- GitHub Pagesへの公開
- AWS S3・CloudFrontへの公開
- AWS CDKによるAWSリソース管理

### 4.2 現段階の対象外

- ログイン、会員管理、データベース、管理画面、CMS
- Contactフォームからの実送信とバックエンドAPI
- 独自ドメイン、Route 53、ACM証明書
- CloudFront標準アクセスログの保存・分析
- 多言語切り替え

対象外項目は不要と確定したものではなく、必要性と費用を確認してから追加します。

## 6. コンテンツ要件

### 6.1 掲載情報

- 表示名: `NOZOMU ORITA`、`nzm_ort`
- 趣味: YouTube、旅行、競技プログラミング
- 外部アカウント: GitHub、AtCoder、Codeforces。Instagramは正式URL確定まで暫定扱い
- 経歴: 幼少期、高校、大学、大学院、社会人

### 6.2 表記ルール

- 見出しは既存デザインに合わせて原則英語、説明本文は日本語とする。
- 日付は、期間なら`YYYY–YYYY`、取得年月なら`YYYY年M月取得`を基本とする。
- 固有名詞と資格名は公式表記を優先する。
- 未完成機能やダミーリンクを、利用可能な機能であるかのように表示しない。
- 他者が権利を持つロゴや認定バッジは、各利用規約を確認し、必要に応じて文字中心の表示へ変更する。

## 8. 制約・前提

- アプリケーションは静的ファイルとして配信し、常時稼働サーバーを持たない。
- Node.jsは22系を使用する。
- AWSの主リージョンは東京リージョン（`ap-northeast-1`）とする。CloudFrontとIAMはグローバルサービスである。
- AWSリソース変更は`infra/`のCDKコードを正とし、原則としてマネジメントコンソールだけで恒久変更しない。
- AWSの学習を兼ねるため、インフラ変更は小さい単位で理解・差分確認・デプロイ・画面確認の順に行う。
- GitHub PagesとAWSは移行確認のため併用中であり、将来どちらを正式公開先とするか再決定する。

## 9. 受入条件

1. `npm ci`、`npm run lint`、`npm run build`が成功する。
2. PC幅とスマートフォン幅で主要セクションを閲覧でき、横スクロールが発生しない。
3. ナビゲーション、AboutへのCTA、Portfolioモーダル、主要外部リンク、Back to topが動作する。
4. Contactが送信不可であることを誤認させない。
5. Pull RequestのCIが成功する。
6. `main`へのpush後、GitHub PagesとAWSのワークフローが成功する。
7. CloudFront URLでHTTP 200となり、画像・動画・CSS・JavaScriptが読み込まれる。
8. S3のパブリックアクセスブロック、暗号化、TLS強制、OAC経由の読み取りを確認できる。
9. 秘密情報がソースと公開成果物に含まれない。

詳細な確認方法は[06-test-specification.md](06-test-specification.md)を参照します。

## 11. 変更管理

要件追加・削除時は、要件IDを再利用せず、状態と理由を残します。実装だけを先に変えた場合も、同じ変更単位で関連する設計書とテスト仕様書を更新します。
