# ポートフォリオサイト要件定義

最終更新日: 2026-09-21  
対象リポジトリ: `portfolio-site`

## 1. 文書の目的

本書は、ポートフォリオサイトの刷新とAWSへの移行について、「何を完成とするか」を定義します。

企業向けシステムのような厳密な要件定義ではなく、個人サイトの開発判断に必要な範囲へ絞った軽量版です。画面上の細かな配置は画面設計、ReactやAWSの実装方法は技術・AWS構成設計で扱います。

## 2. サイトの目的

### 2.1 主目的

Nozomu Oritaの経歴、制作物、資格、技術経験を、初見の閲覧者が短時間で把握できる状態にします。

### 2.2 副目的

- GitHubや競技プログラミングの外部プロフィールへ誘導する
- 研究・制作の実績を、文章だけでなく画像とともに示す
- ReactおよびAWSを用いた設計・構築・運用経験を成果物として示す
- PCとスマートフォンの双方で、破綻せず閲覧できるようにする

### 2.3 想定閲覧者

| 閲覧者 | 知りたいこと | 優先度 |
| --- | --- | --- |
| 採用担当者・面談相手 | 人物像、経歴、資格、成果物の概要 | 高 |
| エンジニア | 使用技術、実装内容、GitHub上の成果物 | 高 |
| 知人・一般閲覧者 | 活動内容、SNS・外部プロフィール | 中 |
| サイト所有者 | 自分の実績を簡単に追加・更新できること | 高 |

## 3. 成功条件

初期リリースでは、次を満たせば成功とします。

1. 主要情報へ、トップからスクロールまたはナビゲーションで到達できる。
2. PC、タブレット、スマートフォンで横スクロールや要素の見切れが発生しない。
3. 制作物と外部アカウントのリンクが正しく開く。
4. `npm run lint` と `npm run build` が成功する。
5. AWS上のHTTPS URLから表示でき、GitHubの`main`更新を安全に反映できる。

アクセス数などの数値目標は、利用目的と計測方法が決まっていないため、初期リリースの成功条件には含めません。

## 4. 対象範囲

### 4.1 初期リリースに含めるもの

- Reactによる1ページ構成のサイト
- ヘッダー、Hero、About、Portfolio、Qualifications、Skill、Footer
- 制作物詳細のモーダル表示
- GitHub、AtCoder、Codeforcesなど外部サイトへのリンク
- レスポンシブ表示
- AWS上での静的サイト配信
- GitHubからAWSへの自動デプロイ
- 最低限のSEO、アクセシビリティ、表示性能対策

### 4.2 初期リリースの対象外

- ログイン、ユーザー登録、管理画面
- データベース
- ブログやCMS
- 決済、予約などの業務機能
- 多言語切替
- Contactフォームからの送信処理
- 高度なアクセス分析、広告配信

Contactは現状画面に存在しますが送信できません。初期リリースでは、非稼働フォームを公開せず「削除する」または「連絡先リンクに置き換える」のどちらかを正式仕様とします。

## 5. 機能要件

優先度は `Must`（必須）、`Should`（できれば実現）、`Could`（将来候補）で示します。

| ID | 要件 | 優先度 | 現状 |
| --- | --- | --- | --- |
| FR-001 | 固定ヘッダーから各主要セクションへ移動できる | Must | 一部対応。`ACCOUNT`の移動先が存在しない |
| FR-002 | Heroで氏名とサイトの性質を認識できる | Must | 対応済み |
| FR-003 | Hero背景動画を自動再生し、再生不可でも内容を読める | Should | 動画は対応。代替静止画は未整備 |
| FR-004 | Aboutで人物像、経歴、研究実績を確認できる | Must | 対応済み。プロフィール画像を設定済み |
| FR-005 | Portfolioの一覧と各成果物の詳細を確認できる | Must | 対応済み |
| FR-006 | 成果物に関連するGitHubまたは公開先へ移動できる | Must | 一部リンク未設定 |
| FR-007 | 資格名と取得年月を一覧で確認できる | Must | 対応済み |
| FR-008 | 使用技術と経験内容を一覧で確認できる | Must | 対応済み |
| FR-009 | GitHubなどの外部プロフィールへ移動できる | Must | 対応済み。InstagramはダミーURL |
| FR-010 | BGMを閲覧者の操作で再生・停止できる | Could | 対応済み。状態表示は未整備 |
| FR-011 | ページ下部から先頭へ戻れる | Should | 対応済み |
| FR-012 | 連絡手段を提示できる | Should | 未決定。現フォームは送信不可 |
| FR-013 | ページタイトル、説明、共有用画像を設定できる | Should | タイトルのみ設定済み |
| FR-014 | JavaScriptエラーや404のない状態で主要導線を利用できる | Must | 要確認 |

## 6. コンテンツ要件

### 6.1 掲載情報

| 分類 | 必須項目 | 任意項目 |
| --- | --- | --- |
| 基本情報 | 氏名、短い紹介 | 顔写真、居住地域 |
| 経歴 | 所属・期間・概要 | 詳細な活動内容 |
| 制作物 | 名称、概要、画像、使用技術 | GitHub、公開URL、担当範囲、成果 |
| 資格 | 資格名、取得年月 | 認定番号、認定リンク |
| 技術 | 技術名、利用経験 | 習熟度、利用年数 |
| 研究 | 発表名・論文名・時期 | 受賞、外部論文リンク |
| 外部リンク | GitHub、AtCoder、Codeforces | Instagram、その他SNS |

### 6.2 表記ルール

- 日本語を基本言語とし、固有名詞や国際発表名は原文を使用する。
- 年月表記は原則として `YYYY年M月` に統一する。
- 英字見出しの大文字・小文字は画面全体で統一する。
- 未設定リンク、ダミーURL、`Not working`などの開発中表記は本番公開しない。
- 資格ロゴやサービスロゴは、利用規約を確認できたものだけを使用する。

## 7. 非機能要件

### 7.1 対応環境

| ID | 要件 |
| --- | --- |
| NFR-001 | 最新版のChrome、Edge、Safari、Firefoxで主要機能が利用できる |
| NFR-002 | 画面幅320px以上を最低対応範囲とする |
| NFR-003 | マウス、キーボード、タッチ操作で主要導線を利用できる |
| NFR-004 | 縦長画面ではHeroを画面全体に固定せず、次の内容が見えてもよい |

### 7.2 表示性能

| ID | 要件 |
| --- | --- |
| NFR-101 | 初期表示に不要な画像・動画を遅延読み込みする |
| NFR-102 | 画像は表示寸法に適したサイズとWeb向け形式へ圧縮する |
| NFR-103 | Hero動画には軽量版と代替画像を用意する |
| NFR-104 | ハッシュ付き静的資産は長期キャッシュし、HTMLは短期キャッシュする |

現状、ビルド対象に約13MBの画像と約5MBのHero動画が含まれます。刷新時の優先改善事項です。

### 7.3 アクセシビリティ

| ID | 要件 |
| --- | --- |
| NFR-201 | 意味のある画像に内容を表す`alt`を付ける |
| NFR-202 | アイコンだけの操作にアクセシブルな名前を付ける |
| NFR-203 | 文字と背景のコントラストを確保する |
| NFR-204 | キーボードフォーカスを視認できるようにする |
| NFR-205 | `prefers-reduced-motion`指定時は動画や動きを抑制する |
| NFR-206 | 見出しレベルを論理的な順番にする |

### 7.4 セキュリティ・プライバシー

| ID | 要件 |
| --- | --- |
| NFR-301 | 全ページをHTTPSで配信し、HTTPはHTTPSへ転送する |
| NFR-302 | S3バケットを公開せず、CloudFrontだけに読み取りを許可する |
| NFR-303 | AWSへのデプロイに長期アクセスキーを使用しない |
| NFR-304 | 公開不要な個人情報、秘密情報、APIキーをリポジトリへ含めない |
| NFR-305 | 外部リンクには必要に応じて`noopener`相当の設定を付ける |

### 7.5 可用性・運用性

| ID | 要件 |
| --- | --- |
| NFR-401 | `main`への変更から、手作業を減らして再現可能にデプロイできる |
| NFR-402 | デプロイ失敗時はGitHub Actions上で原因を確認できる |
| NFR-403 | 直前の正常なGitコミットから再ビルド・再デプロイできる |
| NFR-404 | AWS料金の予期しない増加を検知できるよう予算通知を設定する |

## 8. 受入条件

リリース前に、次の項目を満たすことを確認します。

1. ナビゲーション、CTA、制作物、外部プロフィールの全リンクが正しい。
2. 320px、768px、1440px程度の幅で見切れ・重なり・意図しない横スクロールがない。
3. キーボードだけでナビゲーション、制作物詳細、主要リンクを操作できる。
4. lint、production build、AWSへのデプロイが成功する。
5. CloudFront URLおよび独自ドメイン採用時のドメインからHTTPSで表示でき、S3の直接URLでは閲覧できない。

## 9. 現状確認で見つかった課題

| 優先度 | 課題 | 対応方針 |
| --- | --- | --- |
| 高 | Contactが送信不能のまま表示される | 初期公開前に削除または連絡先リンクへ変更 |
| 高 | ナビゲーションの`ACCOUNT`に対応するセクションがない | About内リンクへ統合するか、ナビ項目を削除 |
| 高 | 大容量画像・動画が初期配信量を増やす | 圧縮、リサイズ、遅延読み込みを実施 |
| 中 | InstagramがダミーURL | 正式URL設定まで非表示にする |
| 中 | 一部画像の`alt`が空または不足 | 装飾画像と情報画像を区別して設定 |
| 中 | HTMLのdescription、OGPが未設定 | 本番公開前に設定 |
| 低 | Bootstrap等の外部CDNとnpm依存が混在 | ビルドへ統合し依存元を整理 |

## 10. 判断待ち

開発を進める前に、所有者が次の3点だけ決めれば十分です。

1. Contactを「削除」「メール等へのリンク」「送信フォーム実装」のどれにするか。
2. 独自ドメインを初期リリースから使うか。
3. BGMを正式機能として残すか。
